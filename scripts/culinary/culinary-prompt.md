# Кулинарен преглед и рецепти за ястията на NutriPlan

Промптът на scripts/culinary/ai-culinary.mjs (Gemini). Същите правила проверява scripts/culinary/validate.mjs.

Входът е JSON масив от шаблони на ястия. Всеки шаблон има:
- id, meals (breakfast | main | snack | late), name (с {GROUP} на мястото на избрания продукт), currentPrep (сегашното кратко приготвяне)
- parts: части на ястието. `ref` е името на частта (PRO, STA, VEG, FAT, FAT2, FRU, MLK, LEG …).
  `options` са вариантите — програмата избира ЕДИН вариант за частта („тиквички + чушки“ = един вариант от два продукта).
  `optional: true` = частта може да липсва изцяло. onlyStyles/onlyPatterns = частта се появява само при тези диети.
- fixed: продукти, които винаги са в ястието; sides: гарнитури, подавани отделно (салата/хляб) — НЕ ги включвай в рецептата.

## А. Кулинарен преглед (строг, но реалистичен)
Мисли като опитен български диетолог и готвач. Отбележи само неща, които реален човек в България би намерил странни,
несъществуващи или неядливи като съчетание / за това хранене. Пример за грешка: „Извара с праскова“ (вече оправено),
„Нахут с домати“ за закуска. Не отбелязвай нормални неща (кисело мляко с плод, овесена каша с банан, пиле с ориз).
Типове находки:
- remove_option: вариант, който не пасва на ястието при НИТО един избор на другите части.
- avoid_pair: вариант на една част, който е странен само заедно с конкретен вариант на друга част (дай и двата).
- wrong_meal: ястието не е подходящо за посоченото хранене (кажи кое хранене е правилното).
- rename: името на шаблона звучи неестествено на български (дай по-добро име със същите {GROUP} плейсхолдъри).
Всяка находка: кратка причина на български.

## Б. Рецепта за всяко ястие
Формат за всяко ястие:
  "<id>": { "time": <цяло число минути общо>, "steps": ["…", "…"], "tip": "…" }
Правила:
1. 2–6 стъпки, всяка до 220 знака, в повелително наклонение, учтива форма („Нарежете“, „Запечете“). Естествен, топъл, ясен български. Без емоджита.
2. Плейсхолдъри: {REF} (напр. {PRO}, {VEG}, {FAT2}) се заменят с избрания продукт в ИМЕНИТЕЛЕН падеж, без член,
   малки букви, напр. „пилешко филе“, „тиквички и чушки“, „кафяв ориз“. Затова пиши изреченията така, че продуктът
   да стои граматически правилно без член и без съгласуване на прилагателно с него:
   ДОБРЕ: „Нарежете {VEG} на хапки.“, „Сварете {STA} според указанията на опаковката.“, „Поръсете с {FAT}.“
   ЛОШО: „Нарежете {VEG}-те“, „Сварения {STA}“, „{PRO}та“.
3. Рецептата трябва да работи за ВСЕКИ вариант на частта (напр. STA може да е булгур, картофи или киноа → „Сварете или
   изпечете {STA}“ / „Пригответе {STA}“). Ако вариантите изискват различна обработка, пиши обобщено.
4. Ако частта е optional, стъпка с нейния плейсхолдър изчезва, когато частта липсва. Затова сложи всеки optional
   плейсхолдър в ОТДЕЛНА стъпка, която може да отпадне, без останалите стъпки да станат безсмислени.
   Задължителните части (optional:false) могат да са в която и да е стъпка.
5. Продукти по име без плейсхолдър: само ако са във fixed, или са ЕДИНСТВЕНИЯТ вариант на дадена част, или са основни
   овкусители (сол, черен пипер, подправки, билки, вода, чесън, лук, лимонов сок, оцет, канела, ванилия).
   Никакви други продукти (не измисляй сирене, мед, захар, масло, ако ги няма в ястието).
6. Числа само за време и температура: „200°C“, „20–25 минути“. БЕЗ грамове, мл, калории, порции, брой лъжици с число —
   количествата идват отделно от програмата. „лъжица вода“ е добре, „2 с.л. зехтин“ не е.
7. tip (по желание, до 160 знака): един практичен съвет (как да остане сочно, как да се приготви предварително и т.н.).
8. Без медицински твърдения, без „здравословно“ обещания.

## Изход
Отговор САМО JSON:
{ "recipes": { "<id>": { "time": 15, "steps": ["…"], "tip": "…" } },
  "audit": [ { "dishId": "...", "type": "remove_option|avoid_pair|wrong_meal|rename", "ref": "...", "option": "...", "with": {"ref": "...", "option": "..."}, "meal": "...", "name": "...", "reason": "..." } ] }
